# JustClick 手动验收指南（迭代 3）

自动测试覆盖数据与规则逻辑；下面这些是浏览器交互，需要人工点一遍。

> 迭代 1/2 的手动步骤（自定义字段、规则表、从当前页学习、填充高亮）仍然适用，见文末「迭代 2 回归」。

## 0. 准备

```bash
npm run build          # 产出 dist/
```

Chrome → `chrome://extensions` → 打开开发者模式 → 「加载已解压的扩展程序」→ 选 `dist/`。

## 1. 自定义字段（对应验收 1）

1. 打开 options 页 →「自定义字段」→「+ 添加自定义字段」。
2. label 填 `期望薪资`，观察 key 自动变成 `custom_field_1`（纯中文无 slug）；改成 label `Expected Salary` 时 key 应变 `expected_salary`。
3. 手动把 key 改成 `expected_salary`，value 填 `30k / 月` → 保存。
4. 刷新页面，确认该行仍在、key 未被重算覆盖。

## 2. 规则表（对应验收 2 / 3）

1. options 页「映射规则」→「+ 新增规则」。
2. 把「匹配文本」改成 `salary`，「匹配方式」选 `contains`，「目标字段」选 `期望薪资 · expected_salary`，站点限制留空。
3. 关掉左侧开关 → 状态提示「已保存规则 …」，刷新后仍是禁用态（验收 3 的持久化）。

## 3. 从当前页学习（对应验收 4 的交互侧）

1. 打开任意一个带表单的招聘页（Greenhouse / Lever 职位页最好）。
2. popup →「从当前页学习」→ 应列出可见的 input/textarea/select，每条显示 label、属性样本、建议选择器。
3. 给某个字段选目标（内置 key 或自定义 key），其余保持「忽略」→「保存规则」。
4. 关掉再打开 popup，重新学习，确认已保存规则在 options 页规则表里可见。

## 4. 填充与高亮（迭代 1 回归）

1. 简历填上姓名 / 邮箱 / 电话 → 在表单页点「一键填充当前页面」。
2. 命中字段应高亮 2 秒；popup 显示「已填 N 项」及缺失项。
3. 禁用规则后再填，被规则覆盖的字段应回退到原来的识别结果（验收 3 的行为侧）。

## 5. 边界

- Chrome 内部页 / 扩展商店页：popup 应提示「这个页面不能操作」，而不是静默失败。
- 隐藏字段、密码框、验证码、搜索框：学习列表与填充都不应出现（`GLOBAL_REJECTS` + `SKIP_TYPES`）。
- 填充永远不点提交按钮。

# 迭代 3：模板 / 报告 / 待填补充

## 6. 三组模板（对应验收 1 / 2）

1. 打开 options 页：应看到「基本信息 / 求职意向 / 教育与其他」三组，每组右上角有「已填 x / y」和一条进度条，顶部有总进度。
2. 填「姓氏=张」「名=三」，把「姓名全名」清空并失焦 → 该框应显示自动拼接的 `张三`；再手改成 `张三丰` → 失焦后仍是 `张三丰`，之后改「姓」不会再覆盖它。
3. 任意输入框失焦后右上角应出现「已保存 ✓ 时间」，**没有保存按钮**；关掉页面重进，值还在。
4. 「教育与其他」→「+ 添加自定义项」→ 输入 `期望薪资` → 回车：该项应出现在第三组，并显示生成后的 key（`cf_xxxx` 形式的确定性哈希）。再添加一次同样的名字 → 不应出现第二行。
5. 「导出的 JSON」用文本编辑器打开：`customFields` 里每项带 `group`，预置项带 `preset: true`；把文件改坏再导入 → 应给出可读错误且不覆盖现有数据；正常导入 → 弹确认框，确认后覆盖。

## 7. 填充报告三区块（对应验收 3）

1. 简历里填姓名/邮箱/电话，找一个只有「姓名/邮箱」的表单页 → popup「一键填充」。
2. 报告应显示「已填 2 项」（`姓名 = 张三` 形式）、「待填 M 项」（页面有输入框但简历没值的字段，比如地址）、「未匹配 K 项」（简历有电话但页面没电话框）默认折叠。
3. 找一个邮箱填得很长的简历 → 值超过 20 字显示省略号，点「展开」看全文。
4. 点「复制报告」→ 粘贴到记事本，应为三段式纯文本。

## 8. 内联补填与待填项（对应验收 4 / 5）

1. 在「待填」那一行输入 `上海市徐汇区…` → 点「补填」：页面上的地址框应被填上并高亮 2 秒，该行消失、计数变成「待填 M-1 项」，**页面不得自动提交**。
2. 关掉 popup 再打开 → 顶部应出现「你有 N 个待填项（上次来自 xxx.com）」，展开可看到字段名、来源站点与时间；「忽略」后该条消失。
3. options 页「待填清单」应显示同一份清单；点「去填写」应定位到模板里对应字段（模板里没有的字段会自动补成自定义项）。
4. 补过的字段再打开 popup 时不应再出现在待填里。

# 迭代 4：AI 简历导入（BYOK，手动验收）

> 自动化测试覆盖的是纯函数（提示词 / 解析 / 合并 / 错误分类 / 设置持久化 / mock fetch）。
> 下面 4 组必须在**真实 Chrome + 真实接口**里点一遍，Node 里跑不出来。

## 9. 供应商设置与测试连接（对应验收 5 的交互侧）

1. `npm run build` → 重新加载 `dist/` → 打开 options 页，滚到「AI 简历导入（自带 API Key）」。
2. 三个输入应有默认值：baseURL `https://api.deepseek.com/v1`、模型 `deepseek-chat`，key 为空；右上角徽标显示「未配置」。
3. 填一个**错误** key → 点「测试连接」：2 秒内应显示 `✗ API Key 无效或没有权限（401/403）…`，**不能**是长长的堆栈。
4. 填正确 key → 点「测试连接」：应显示 `✓ deepseek-chat（xxxms）`，徽标变「已配置」。
5. key 输入框应显示为圆点（`type=password`）；点「清除」→ key 清空、徽标回「未配置」、baseURL 与模型保留。
6. 把 baseURL 改成不存在的域名 → 测试连接应显示网络类错误（`网络请求失败…`），页面不崩。
7. 把模型名改成不存在的值 → 应显示 `接口路径或模型不存在（404）…`。
8. 刷新 options 页 → 三项配置仍在（`jc.aiSettings`）；**导出 JSON** 后打开文件，里面**不应**出现 apiKey。

## 10. PDF / TXT 上传与文本提取（对应验收 3 / 6）

1. 把一份**文字版 PDF** 拖进虚线框（或用「选择文件」）：状态应先显示「提取 PDF 文本：x / y 页…」，完成后显示字符数与「点开始解析」。
2. 上传 `.txt` 简历：应直接读出文本。
3. 上传**扫描件 PDF**（图片型）：应提示「该 PDF 没有可提取的文本层，可能是扫描件…请用粘贴文本方式」，而不是静默空结果。
4. 传一个 3 万字符以上的长文档：应提示「超过 30000，解析时只发前 30000 字符」，且提示文案与实际行为一致。
5. 打开 DevTools → Network：PDF 解析期间**不应**有任何外域请求（pdf.js 全部来自 `chrome-extension://`）。
6. 控制台不应出现 `pdfjsLib` 相关的模块加载错误；若出现，检查 `dist/vendor/pdfjs/` 是否随构建产出。

## 11. 解析 → 预览 → 确认写入（对应验收 1 / 2 / 4）

1. 配上有效 key，上传简历后点「开始解析」：状态应显示「AI 正在解析，最长 60 秒…（简历文本只发往 <你的 baseURL>）」。
2. 成功后应出现预览表：每行 = 字段名 + key + 可编辑的 AI 值 + 「覆盖」勾选框 + 说明（新增 / 已有 xxx（默认保留））。
3. 手工改某行的值 → 点「确认写入」：写入的应是**你改后**的值，可在模板里看到。
4. 简历里已有邮箱，AI 也给了邮箱 → 默认应**保留原值**（说明列显示「已有：…（默认保留）」）；勾上「覆盖」再写入 → 变成 AI 的值。
5. 勾「跳过」某行 → 该字段不应被写入。
6. 写入后状态应显示「已写入 N 项…可到任意申请页点 JustClick 一键填充」，且**不会**自动打开新标签页。
7. 故意把接口地址指向一个返回 HTML 的地址 → 应显示「接口返回的不是 JSON…」而不是白屏。

## 12. 隐私与安全（底线，逐条确认）

1. 全程只看 Network：简历文本只发往**你自己配置的 baseURL**，没有第三方域名。
2. 控制台搜索你的 key 片段：**不应**出现（`ai-client.js` / `ai-settings.js` / `options.js` 里没有任何 console 输出 key）。
3. AI 导入全程不触碰任何网页表单，也不会提交任何东西。
4. `dist/vendor/pdfjs/` 里只有 `pdf.min.mjs` / `pdf.worker.min.mjs` / LICENSE，没有从网络加载的代码。

# 迭代 5：iframe / Shadow DOM / 中国站点（手动验收）

自动测试用 stub DOM 与字段描述符覆盖逻辑；真实站点结构与登录态必须人工点。

## 13. iframe 表单（对应验收 1）

1. 找一个申请表单嵌在 iframe 里的 Greenhouse / Lever 职位页（或本地写一个 `<iframe src="form.html">` 的两页测试站）。
2. 简历填好姓名 / 邮箱 / 电话 → popup「一键填充当前页面」。
3. 预期：popup 顶部文案含「扫描 N 个 frame」且 N ≥ 2；报告里子 frame 的字段出现在「已填」；同一个 key 在多个 frame 出现时只显示一条。
4. 关掉某个 iframe（或让它 404）再填一次：失败的 frame 不应让整次填充报错，其它 frame 仍正常。
5. 报告「待填」行里跨 frame 重复的 key 只出现一次，并带「（frameA、frameB）」来源标注。

## 14. 多 frame 学习（对应验收 6）

1. 同一个多 frame 页面 → popup「从当前页学习」。
2. 预期：列表同时包含主页面与子 frame 的字段，每项显示「域名/路径 · 字段名」；字段数 ≥ 2 个 frame 时状态行提示「共 N 个 frame、M 个字段」。
3. 给子 frame 的字段选目标 → 保存规则 → 规则表里 `sitePattern` 应是**主页面 host**，不是子 frame 域名。

## 15. Shadow DOM（对应验收 2，Workday 系）

1. 打开一个 Workday 申请页（或本地页面：`host.attachShadow({mode:'open'})` 两层嵌套，内层放姓名/邮箱/密码/隐藏 input）。
2. 「一键填充」后：shadow 内的姓名 / 邮箱被填上；密码框、`display:none`、`aria-hidden` 的框不被填。
3. 已填列表里 shadow 命中项应带 `shadow` 角标。
4. 「从当前页学习」能列出 shadow 内字段，selector 形如 `#host >>> div:nth-of-type(1) >>> input:nth-of-type(2)`。
5. 报告「补填」对 shadow 字段也能定位（`JC_FILL_ONE` 走 `resolvePath`）。

## 16. 中国五站点（对应验收 3，需登录态）

逐个站点打开投递/快速投递弹窗，确认对应输入框被填、且没有误填「当前薪资 / 公司名 / 技能」等：

| 站点 | 重点字段 | 预期 |
| --- | --- | --- |
| Boss 直聘 | `name=geekName` / `name=geekMobile` / 弹窗内 `name=email`；另需确认弹窗里用的是通用属性名时也命中：`name=name` / `name=phone` / `name=email` | 姓名 / 手机号 / 邮箱，confidence 满命中，且 `ats` 是 `zhipin`（不是 `lever`） |
| 智联招聘 | `name=userName` / `id=resumeName` / `name=mobile` | 姓名 / 手机号 |
| 前程无忧 51job | `id=inputRealName` / `name=mobilePhone` | 姓名 / 手机号 |
| 拉勾 | `name=userName` / `name=phone` | 姓名 / 手机号 |
| 猎聘 | `name=realName` / `id=name` / `name=mobile` | 姓名 / 手机号 |

另需确认：
- 中文 label 直接可见即命中，不需要先建用户规则：`期望薪资` / `到岗时间` / `学历` / `学校` / `专业` / `工作年限` 分别对应 `expected_salary` / `available_date` / `education` / `school` / `major` / `experience_years`（`学历` 不要落到 `school`，`学校` 不要落到 `education`）。
- 学历下拉：简历写「本科」时能选中「本科及以上」；写「硕士」能选中「研究生」；到岗写「随时」能选中「随时到岗」或「立即到岗」。
- 期望薪资不会填进「当前薪资」输入框（负向词「当前 / 现有」生效）。
- 站点改版导致规则失效时，仍能靠中文词库或「从当前页学习」补救。

> 以上四节没有自动断言；自动测试只证明「给定描述符 / stub DOM 时逻辑正确」，不代表真实站点已逐站回归。
